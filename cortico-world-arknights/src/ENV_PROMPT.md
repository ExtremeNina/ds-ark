明日方舟 PC 客户端是本机一个可以被截屏、被点击的窗口（当前匹配关键字：{{arknights.windowMatch}}）。使用时机与约束：

- 任何操作前先调用一次 ark_connect。它没成功时先确认游戏是否已经启动、窗口标题是否与上面的关键字相符，再决定是否让用户改配置；不要连续重试同一个调用。
- 需要看画面时才调用 ark_screencap。每次只取当前一帧，不要连拍轮询：连续截图既不会得到更新的战场信息，也会白白占掉上下文。
- 要让游戏停住或继续时调用 ark_set_paused，传 true 停、传 false 继续。默认情况下回执会附上点击之后抓的一帧，用那张图自己判断有没有真的暂停或继续；World 不做识别，也不替你下结论。回执没有附带图片时（配置里关了补拍、端点不接受图片，或补拍失败），再调用一次 ark_screencap 确认。
- 点击与拖拽都可能被游戏直接忽略（后台合成消息、权限不对等都会这样）。用户说「没反应」时，先重新截一帧确认当前状态，不要连续重复调用 ark_set_paused 或 ark_deploy；确认没生效就如实说明可能的原因（坐标没校准、输入方式不适用、游戏与桌宠权限不一致），把处理交给用户。
- 需要数字类战况时调用 ark_battle_state：它抓一帧、读出费用、生命值、剩余敌人、暂停横幅与手牌费用，并把同一帧作为附件给你。它只读取帧，不点任何东西，也不会替你暂停；识别不到的项会在回执里列为「没读到」。识别失败时它照样给图，这时直接用眼睛看（模型随包提供，正常不需要配置 resourceDir）。数字来自本机 OCR，可能有误，和画面对不上就以画面为准，不要向用户断言精确数值。
- 要部署干员时调用 ark_deploy：从附件画面里量出手牌位置与目标地块，传 0~1 的归一化坐标 card / tile，再给朝向 up / down / left / right。它只发两次拖拽，回执只说「已拖拽」，落没落位、朝向对不对由你从附件里看。想稳一点就先 ark_set_paused(true) 再部署，部署完 ark_set_paused(false)；拖完先看图再决定下一步，不要连发，姿态不对就重新调一次而不是叠加多次拖拽。
- 本版认不出干员名字、职业、关卡名、敌人类型和地块坐标：这些只能从画面里看。不要凭画面里的文字猜数值，也不要声称自己已经知道战场布局。
- 只操作明日方舟窗口。画面仍是 16:9 时换分辨率不必重新校准，坐标会按比例缩放；换成 16:10、21:9 等比例后暂停坐标不再保证，需要用户按 README 的步骤重新标定 pauseButton（日志里会提示一次「不是 16:9」）。

## 找按钮、走界面

除了战斗读数，还有三个通用动作：`ark_ocr` 读全屏文字与归一化坐标、`ark_click` 点一个点、`ark_swipe` 从一点拖到另一点。用户说「去打 1-7」这类指令时，按这个循环走：

1. `ark_ocr` 拿当前界面的所有文字与坐标（默认只回文字，省 token）。
2. 先判断「这是哪一屏」：首页 / 终端 / 作战 / 关卡列表 / 编队 / 战斗中 / 结算。判断不了就停下来问用户，不要猜着点。
3. 从文字里找目标（如「终端」「作战」「1-7」「开始行动」），用它的**中心坐标**调 `ark_click`（不要用框的左上角）；目标不在当前列表里就用 `ark_swipe` 往上滑，再读一次屏。
4. 点完再 `ark_ocr` 一次：界面变了才继续；没变说明这一下没生效，先说明情况，不要连点。
5. 进入战斗后转用 `ark_battle_state` + `ark_deploy` 的循环。

同一个目标最多点两次；进入关卡会消耗理智、点「开始行动」会真的开打，执行前先向用户说明。

## 让模型自己打完一局

用户说「你自己打一局」时，按下面的循环走，直到结算：

1. `ark_battle_state` 拿帧、费用、生命、剩余敌人与手牌费用。
2. **先看回执有没有说「本局已结束 / 本局失败」**：有就停下，把结果和最后一帧如实报给用户，不要再下干员。
3. 还在对局中：从附件里量一张手牌与一个地块（0~1 归一化），调用 `ark_deploy`；朝向按敌人来向选。
4. 费用不够或还在回费：`ark_wait` 等 2000~5000 毫秒再读状态，不要用连续截图硬等。
5. 漏怪、想重新判断局面时 `ark_set_paused(true)`，想好了再 `false` 继续。

原则：一次只下一个干员，下完先看附件再决定下一步；同一步连续失败两次就停下来问用户，不要盲目重试；费用、敌人数量以回执和画面为准，读不到就说读不到。

## 接任务：打哪关、打几局

用户会给一句话，比如「去打一遍 1-7」「随便找几个简单的关卡打」「刷三把 CE-5」。先拆成三件事：打哪几关、打几局、有什么限制（理智、次数）。拆不出来就问一句，不要自己编。

挑关顺序：

1. 用户点名了关卡 → 就打那一关。
2. 用户没点名 → 优先从推荐清单里挑（配置项 `easyStages`）：{{arknights.easyStages}}。
3. 清单是「（未配置）」→ 自己按画面挑，但动手前先告诉用户你打算打哪几关。

每一局：

1. 用上一节的方式走到关卡入口（首页 → 终端 → 作战 → 选关）。
2. 进关卡前确认理智够；不够就停下说明，不要硬进。
3. 到编队界面点「开始行动」；出现编队为空或助战提示时先如实说，再按用户指示处理。
4. 战斗内用上面「让模型自己打完一局」的循环。
5. 结算后认结果，点返回，回到关卡入口再打下一局。
6. 每局结束用一行汇报：关卡 / 结果 / 用时；全部打完给一个总汇总。

护栏：同一个界面连续两次没变化就停；某一局失败不要自动重来，先问用户；任何消耗理智或资源的操作，执行前说明。
