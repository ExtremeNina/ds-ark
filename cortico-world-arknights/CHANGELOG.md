## 0.3.0

- 新增选关与集成战略导航：`ark_enter_stage`（资源本 CE/LS/CA/AP/SK、芯片本 PR、主线、已收录 SideStory）与 `ark_open_roguelike`（集成战略主题页）。工具数从 9 增到 11。
- 内置本项目自有的 MaaFramework pipeline（`assets/resource/pipeline/`，六个文件）：动态文本用哨兵 + `pipeline_override` 传入；滚动用 `Find` + `Scroll` 自循环与 `max_hit` 限次；不复制 MAA 的 JSON/模板，坐标取自 MAA 实测值（快照 2026-10）。
- 新增 `src/mfw/runtime.ts`：Resource/Tasker 的唯一持有者，OCR 与 pipeline 共用，20 MB 模型只加载一次；`post_bundle` 缺失时 pipeline 能力降级为可读原因，OCR 不受影响。
- 新增 `src/mfw/pipeline.ts`：`post_task` 执行入口、60 秒总超时后 `post_stop`、从任务明细还原节点轨迹；同一时间只允许一个任务。
- `ark_enter_stage` 默认只到编队页并复核「开始行动」；`start: true` 时先解析理智，读不全或不够就一次点击都不发。`ark_open_roguelike` 到主题页即停，不点「开始探索」。
- 失败回执包含执行轨迹、最后节点与当前画面文字，零点击；`navMaxScrolls` 配置覆盖滚动节点的 `max_hit`。
- 冒烟脚本新增 `--ping` / `--enter <代号>` / `--roguelike <主题>`，真机校准顺序：Ping → 资源本 → 主线 → 活动 → 主题页，只调 ROI 不改节点结构。
- 明确资源边界（Agent.md / README / AGENTS.md / assets/README）：仓库只放代码与自有 pipeline，不打包 MAA 的 `tasks/`、`template/`、`copilot/`、`roguelike/`、`Arknights-Tile-Pos/`；OCR 模型继续随包。上架后由扩展页 README 详述资源来源与安装。
- 真机实测修正：`ark_swipe` 的最小位移从 2 像素放宽到 1——3D 章节地图/战场上 `ark_click` 会被游戏当成镜头微移，1px 微拖拽才是点开关卡牌的可靠手势。
- 环境提示词新增「主线的两级导航」：曲谱画廊默认停在最新章节（先读屏判断当前卡再滑）、画廊层找不到目标章节就停的层级护栏、章节地图的小步长拖拽与 ◀/▶ 切集、3D 场景用 1px 微拖拽代替点击。
- 测试新增：代号归一化与路由、pipeline JSON 结构校验（节点唯一、next/on_error 存在、禁止 MAA 字段）、假 maa 的 bundle/override/超时/停止，以及两个工具的成功/失败/未连接用例。

## 0.2.0

- 内置 OCR 模型：`assets/resource/model/ocr/` 携带 PP-OCRv6 small（`det.onnx` / `rec.onnx` / `keys.txt`），npm 包体积随之增大，但不再需要本机装 MAA。
- `worlds.arknights.resourceDir` 从「必须配置」降级为「可选覆盖」：留空即用包内模型；填了就优先用填的目录（平铺三件套，或带 `model/ocr` 的资源包根），缺件时自动回落到包内模型。
- 模型校验从「目录里有任意 `.onnx`」改为「三件套存在且非空」：`post_ocr_model` 对缺件目录会假成功，直到识别才 0 行，现在缺件直接跳过并在回执里写明缺哪个文件。
- 删除对 MAA 5/6 `PaddleOCR` / `PaddleCharOCR` 布局的探测：那套 `det/inference.onnx` 与 MaaFramework 的固定文件名不兼容，属于永远失败的候选。
- 未配置 `resourceDir` 时不再直接返回「这台机器上没有配置 OCR」。
- 新增 `tests/ocr.test.ts`：候选顺序与去重、内置路径解析、三件套缺件与空文件判定。
- 修复战场读数三处偏差：`O/11` 里的 0 被识成字母 O 时按数字语境纠错（`PAUSE` 不受影响）；`hand.y` 下界 0.86 → 0.83，整排卡费不再落到 unknown；`cost.y` 上限 0.93 → 0.82，最右一张卡的费用不再被当成部署费用。
- 手牌卡费容忍图标前缀（`N16` → 16）；三位数是邻卡粘连，按「去首位 / 去末位 + 费用上限 40」拆回两位（`118` → 18、`167` → 16、`819` → 19），拆不出合法值才丢弃。
- README 补「换 `ppocr_v6-medium`」的步骤（解压覆盖包内目录，或用 `resourceDir` 指向外部目录），用于改善小字漏检。
- 手牌改为两路识别：整帧一次 + 底部手牌条裁切后**转灰度**再一次，按横向位置归并去重。实测同一帧的手牌从 8/12 提到 11/12，此前一直读不到的 24 费（压在浅色立绘上，彩色下 det 不出框）只有灰度那一路能读到；代价是每次识别多约 0.3 秒。
- 新增 `src/mfw/png.ts`：纯 TS 的 PNG 解码/编码/裁剪/灰度（只用 `node:zlib`）。解码失败或格式不支持时自动退回单路识别，不会影响主流程。
- `ark_battle_state` 增加结算判定：认到「行动结束 / 作战胜利 / MISSION ACCOMPLISHED」为胜利，「作战失败 / 行动失败 / MISSION FAILED」为失败（同帧两者都出现时按失败算）；结构化输出新增 `result`，已结算时不再列「没读到」。
- 新增工具 `ark_wait { ms }`：只睡不动作（钳制 0~10000 毫秒），用于等费用回复，避免用连续截图硬等；不截图、不点击。
- 新增 `BATTLE_PLAYBOOK.md`：读状态 → 看结算 → 选牌下干员 → 等费用 → 再看状态的循环与决策规则，并写进环境提示词；模型可在 Coopanion 里据此自己打完一局（不联网、不需要 API key）。
- 冒烟脚本新增只读 `--watch`：每 3 秒读一次战场，认到结算自动退出。
- 冒烟脚本新增 `--auto`：本地自动打一局（固定策略，不调模型）。费用够就下最左一张、往候选地块轮流试，靠「费用有没有掉」判断落位，认到结算退出；候选地块可用 `--auto-tiles` 覆盖，步数上限 `--auto-max`。
- 部署时序可配置：新增 `deployHoldMs`（默认 260）、`deployGapMs`（默认 0）、`deployDirectionMs`（默认 160），两步拖拽之间会真的停顿。默认值与此前常量一致，不配置时行为不变；真机拖拽成功率低时按 README 的「部署成功率低时怎么调」逐个调。冒烟脚本可用 `--hold / --gap / --dir` 临时覆盖，不必改配置文件。
- 新增三个通用动作工具，工具总数从 6 增到 9：`ark_click`（按归一化坐标点一次，可选 `expect` 轮询画面里是否出现某段文字）、`ark_swipe`（`repeats` 连续滚动关卡列表）、`ark_ocr`（全屏文字 + 文字中心与框的归一化坐标，默认最多列 40 行、可调；只读、默认不附图）。
- 新增 `easyStages` 配置（逗号分隔的推荐关卡）：模型接「随便打几关」时优先从清单里挑，留空则按画面自选并先征得同意。
- 环境提示词新增「找按钮、走界面」与「接任务：打哪关、打几局」两节：导航循环（读屏 → 定位文字 → 点击 → 复核 → 无效就停）、多局编排与失败预算；`describe.json` 逐字同步。
- 冒烟脚本新增 `--ocr-all` / `--click-at` / `--swipe`，便于真机单步调试导航。
- 新增 `tests/actions.test.ts`（点击/拖拽的坐标与夹取）与导航相关的工具级用例。
- 新增真机整帧回归用例：`O/11`、`N16`、最右卡 `24` 与部署费用 `29` 同帧断言，三处修复任一回退都会红。
- 手牌不再冒出「4 费」这类假卡：`hand.y` 收到 `[0.83, 0.875]`，并在解析时按 y 中位数剔除不在卡费那一排的数字（卡面下沿的图案会被读成单个数字）。
- 暂停按钮在非 16:9 画面上改为按「距右边缘的余量」换算：16:9 下像素值不变，4:3 下比按宽度比例少偏 10px。
- 文档补「分辨率 / 窗口比例 / 全屏」一节：说明帧会被缩到短边 720、4K 16:9 无需配置、上下黑边会压缩内容区、改窗口大小后要先抓一帧。
- 「不是 16:9」的提示按偏差分级：偏差 ≤0.08（16:10、1.71:1 这类）只发 `info`，说明暂停按钮的 x 已按右边缘余量换算、只有黑边才需要重标；偏差更大才 `warn` 并要求重标。
- 顶部条上界（x=0.72）补注释并加回归：右上角的 `1X` / 暂停图标会被读成 `I1`，纠错后变成 `11`，不能被当成生命值。

## 0.1.0

- 首个版本：`ark_connect`、`ark_screencap`、`ark_set_paused` 三个工具，挂载事件 `arknights.ready`。
- 连接国服《明日方舟》PC 客户端窗口（Win32 控制器），支持后台截图方式与静默输入方式配置。
- 默认输入方式改为 `AnchoredTouch`：实测 `SendMessage` 点不中右上角暂停键，`AnchoredTouch` 能点中且不抢前台。
- 暂停按钮默认坐标改为实测值 `0.966 / 0.071`（帧坐标 1236,51 按 `(边长-1)` 归一化），仅在 16:9 下保证。
- 新增 `verifyAfterClick`（默认开）：暂停/恢复点击后自动补拍一帧作为附件，让模型凭画面自行判断；补拍失败只降级为文字回执。
- 新增画面比例自检：首帧不是 16:9 时记一条日志提示重新标定，每个连接只提醒一次，不进模型上下文。
- 暂停按钮按画面比例校准，同一宽高比下换分辨率不需要重新配置。
- 新增只读工具 `ark_battle_state`：抓一帧，用本机 MAA 资源包里的 OCR 模型读出费用、生命值、剩余敌人、暂停横幅与手牌费用，并附上同一帧。读不到的项列为「没读到」，不当 0；暂停态是三态（认到横幅 / 没认到横幅）。没有 `resourceDir` 或模型加载失败时只给图，不报失败。
- OCR 只加载用户本机资源包里的模型（`Resource.post_ocr_model` + `Tasker.post_recognition`），不打包、不下载、不联网，也不加载 pipeline、不接管截图与点击。
- OCR 模型路径按 MAA 5/6 的 `<资源根>/PaddleOCR`（`det/`、`rec/`、`keys.txt`）优先探测，兼容 `PaddleCharOCR` 与旧版 `model/ocr`；目录里没有 `.onnx` 时跳过，避免 `post_ocr_model` 对空目录返回成功而假装加载好（真机上表现为「加载自根目录」但识别 `det=0 rec=0`）。
- 新增工具 `ark_deploy`：按模型给的 0~1 归一化坐标与朝向发两次 `post_swipe`（手牌 → 地块 → 朝向）；参数不合法时一次手势都不发，地块贴边拖不出方向时直接拒绝；回执只说「拖拽已发出」，不声称部署成功。
- 新增 `src/battle/`：区域归类（顶部条 / 中央横幅 / 右下费用 / 底部手牌）、结构化状态与缺项清单、部署几何，全部是纯函数并有单测。
- 尺寸告警文案去误报：控制器尺寸与帧尺寸不同说明是 MaaFramework 把短边缩到 720，只有控制器尺寸远大于窗口且帧里能看到桌面时才是整屏抓取。
- 冒烟脚本新增 `--state` / `--ocr` / `--deploy` / `--resource`，可单独验识别、验部署，并打印原始识别明细用于校准区域。
- 原生绑定懒加载：未安装或加载失败时工具返回可读原因，World 仍能正常构造与挂载。
- 不含自动战斗、选关与 Copilot 作业回退，不发网络请求，包内不携带任何素材（含 OCR 模型）。
